A tese

Todo revisor de IA afirma.
Nós provamos.

Promotores acusam. Um advogado testa — ele não argumenta, executa. Um juiz sentencia com regras determinísticas. 

pytest no commit base  →  exit 0   (a invariante valia)
pytest no commit head  →  exit 1   (o PR quebrou)
pytest no commit base  →  exit 0   (não é teste intermitente)

O veredito final é um exit code, não opinião de modelo.

POST /documents/11/share?email=nonexistent' OR '1'='1

O contraste é a prova. Duas linhas, e o revisor verifica sozinho — sem precisar acreditar em nós.

Backup · a escada da severidade

A nota mede a força da prova, não a gravidade da categoria

o que temos na mão                                    teto
─────────────────────────────────────────────────────────────
teste passa no base e falha no head                   MÉDIA
   (causalidade: foi esta mudança que quebrou)

\+ chamada HTTP contra o app rodando                   ALTA / CRÍTICA
   (alcance: dá para fazer isso agora, de fora)

crítica sem árbitro citado                            SUSPEITA
execução falhou, recusa, timeout                      INCONCLUSIVO

Aceitamos subestimar um bug real para nunca superestimar um que não existe. E nada some: severidade é ordem de leitura, não decisão de incluir.

Backup · as seis regras do juiz

R0  o artefato ganha do advogado quando os dois discordam
R0b quem decide "prova ponta a ponta" é o artefato HTTP, sempre
R4  refutado em injection com app sem modelo → INCONCLUSIVO
R3  execução falhou → INCONCLUSIVO, nunca absolvido
R1  crítica sem árbitro citado → SUSPEITA
R2  prova que não é ponta a ponta não passa de MÉDIA

Seis funções em Python. Rodam em milissegundos, sem rede e sem modelo, cada uma com teste. É isso que faz “o LLM não sobrescreve o exit code” ser garantia em vez de intenção.
